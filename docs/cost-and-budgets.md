# 비용과 예산 (Cost & Budgets)

## 개요

CLOSELLER 1차 MVP의 비용 설계 목표는 다음과 같습니다.

- **Free Tier / 저비용 범위 유지**: 모든 AWS 리소스를 가능한 한 무료 한도 또는 소액 범위 안에서 사용합니다.
- **상시 유료 리소스 미사용**: 켜 두기만 해도 시간당 요금이 발생하는 리소스(EC2, RDS, NAT Gateway 등)를 정의하지 않습니다.
- **외부 호출(SerpApi) 비용·한도 보호**: 유일한 외부 유료 경로인 SerpApi 호출을 캐시·호출 상한·스로틀로 여러 겹 보호하여, 예상치 못한 과금을 막습니다.

이 문서는 비용이 어디서 발생할 수 있는지, 어떻게 막는지, 그리고 초보자가 AWS Budgets로 예산 알림을 설정하는 방법을 안내합니다.

## 비용 설계 표

아래 표는 `design.md`의 "비용 설계" 내용을 기준으로 정리한 것입니다.

| 항목 | 설계 | 효과 |
|------|------|------|
| DynamoDB | Provisioned 소용량(무료 한도 대상) + TTL 적용 | 적은 읽기/쓰기 용량으로 무료 한도 안에 머무르고, TTL로 오래된 항목을 자동 삭제해 저장 용량과 비용을 억제 |
| 상시 유료 리소스 | EC2 / RDS / NAT Gateway 등 **미정의** | 켜 두기만 해도 과금되는 리소스를 아예 만들지 않아, 유휴 상태의 시간당 요금이 발생하지 않음 |
| CloudWatch 로그 | 보존 기간 **14일** | 로그를 무한히 쌓지 않고 2주 후 자동 만료시켜 로그 저장 비용을 제한 |
| Lambda | 작은 메모리 + 짧은 타임아웃 | 호출당 과금(메모리 × 실행 시간)을 낮추고, 비정상적으로 오래 도는 호출을 차단 |
| SerpApi 비용 보호 | SHA-256 캐시(24시간) + 월간 상한(기본 200) / IP 일일 상한(기본 5) + API Gateway 스로틀(rate 2 / burst 5) | 같은 이미지는 재검색하지 않고(캐시), 전체·IP별 호출 수를 상한으로 막고, 순간 폭주를 스로틀로 눌러 외부 유료 호출을 여러 겹으로 보호 |
| S3 수명 | Lifecycle **1일 자동 삭제** + 검색 완료 즉시 원본 삭제(이중) | 업로드 이미지를 Lifecycle로 1일 내 자동 정리하고, 검색이 끝나면 즉시 삭제하는 이중 장치로 저장 비용과 데이터 잔존을 최소화 |

## 호출 한도 요약

SerpApi 호출 비용을 막는 핵심 장치는 **환경변수로 조정되는 호출 한도**입니다. 값은 `.env.example`과 배포 설정에서 관리합니다.

| 환경변수 | 기본값 | 설명 |
|----------|--------|------|
| `MONTHLY_CALL_LIMIT` | `200` | 앱 전체의 **월간** SerpApi 호출 상한. 이 수를 넘으면 신규 외부 검색을 막습니다. |
| `IP_DAILY_LIMIT` | `5` | **IP별 하루** 검색 상한. 한 사용자가 과도하게 호출해 비용을 유발하는 것을 막습니다. |
| `THROTTLE_RATE` | `2` | API Gateway 초당 평균 처리율(rate). 평상시 요청 속도를 제한합니다. |
| `THROTTLE_BURST` | `5` | API Gateway 순간 허용량(burst). 짧은 순간의 요청 폭주를 흡수하되 상한을 둡니다. |

**무료 한도 대비 버퍼**: SerpApi 무료 플랜의 월간 한도는 **250회**입니다. 앱 상한을 그보다 낮은 **200회**(`MONTHLY_CALL_LIMIT` 기본값)로 설정해 **약 50회의 버퍼**를 둡니다. 이 여유분 덕분에, 상한에 도달하더라도 무료 한도를 넘겨 과금되는 상황을 방지할 수 있습니다.

> SerpApi 한도와 외부 서비스 상세(역할, 사용 이유, 무료 한도 수치)는 [docs/external-services.md](./external-services.md)를 참조하세요.

## AWS Budgets 예산 알림 설정 (초보자용)

실제 비용이 예상을 벗어나는지 **이메일로 미리 알림**을 받기 위해, AWS Budgets에 소액 월 예산을 설정하는 것을 권장합니다. AWS Budgets 자체는 소수의 예산까지 무료로 사용할 수 있습니다.

### 권장 설정값

- **예산 유형**: 비용(Cost) 예산, 주기 **월간(Monthly)**
- **예산 금액**: 소액(예: **$1 ~ $5**) — MVP는 거의 무료 범위이므로 작은 금액으로 설정해 조금만 비용이 생겨도 바로 알 수 있게 합니다.
- **알림 임계값(실제 비용 기준)**: **50% / 80% / 100%** 세 단계
- **알림 수신**: 본인 이메일 주소

### 방법 A — AWS 콘솔(가장 쉬움)

1. AWS 콘솔에 로그인한 뒤 상단 검색창에 **Budgets**를 입력해 이동합니다.
2. **Create budget(예산 생성)** → **Cost budget(비용 예산)** 선택.
3. 주기를 **Monthly**로 두고, 예산 금액에 소액(예: `3` USD)을 입력합니다.
4. **Alerts(알림)** 단계에서 임계값 **50%**, **80%**, **100%**를 각각 추가하고, 기준을 **Actual(실제 비용)**으로 설정합니다.
5. 각 임계값에 본인 **이메일 주소**를 입력합니다.
6. 검토 후 **Create budget**으로 저장합니다.

### 방법 B — Windows PowerShell(AWS CLI)

CLI로도 예산을 만들 수 있습니다. 예산 정의와 알림 정의를 JSON으로 준비한 뒤 `aws budgets create-budget`을 사용합니다. 자세한 단계와 예시 명령은 설정 가이드의 Budgets 단계를 따르세요.

> 상세 설정 절차(콘솔/PowerShell 공통)는 [docs/setup-guide.md](./setup-guide.md)의 **AWS Budgets 알림** 단계와 교차 참조하세요.

## 과금 모니터링 권장

예산 알림과 함께, 다음을 주기적으로 확인하면 비용을 안전하게 관리할 수 있습니다.

- **AWS Cost Explorer / 청구 대시보드 확인**: AWS 콘솔의 **Billing(청구)** 대시보드와 **Cost Explorer**에서 서비스별 비용 추이를 정기적으로(예: 주 1회) 확인합니다.
- **사용 후 리소스 정리**: 개발·테스트가 끝나면 배포한 스택을 삭제해 불필요한 비용을 원천 차단합니다. 정리는 `sam delete`로 수행합니다(🔒 승인 필요 작업).

> 리소스 정리 방법(명령과 순서)은 [docs/setup-guide.md](./setup-guide.md)의 **정리 방법** 단계를 참조하세요.

## 승인 규칙 (비용 발생 작업)

다음 작업은 **비용이 발생하거나 되돌리기 어려운** 작업이므로, 사용자 승인 전에는 실행하지 않고 **명령어와 예상 영향만** 제시합니다.

- `sam deploy` (AWS에 리소스 배포)
- AWS 리소스 생성 / 변경 / 삭제 (예: `sam delete`)
- 실제 SerpApi 호출 (외부 유료 호출)

반대로, 로컬 파일 생성, 빌드, 테스트, `sam validate`, `sam build`는 비용이 발생하지 않으므로 승인 없이 수행합니다.
